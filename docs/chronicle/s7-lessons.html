S7 · the autopsy

Redirects, mistakes, lessons

learn by doingrelearn by redoing

This is the most valuable slide, because it's where the "build it rough, then study it" method pays out. The app was assembled fast, with AI agents, by someone learning the front end as they went. Every wobble below was real. None of them are embarrassing — they're the syllabus. We catalogue each, name the lesson, and carry the fix into the rebuild.

Redirect 1 — coloring everything, then pulling it back

e7f2843 color-coded resource cards across the whole UI. The very next commit, 47464b8, restricted it to the schedule board.

What happenedWhyLesson
A "nice" visual idea applied globally made the UI noisy, so it was scoped back one commit later. You genuinely cannot judge "too much" until it's on screen. Color is information; spend it where it means something (the board), not everywhere. Visual decisions need eyes, not logic. Ship it, look at it, be willing to undo. Small isolated commits make undo cheap.

Redirect 2 — navigation took three tries

641fd78 (hero table-of-contents) → 9c9993f (chips become a section menu) → 162a4e8 (simplify). Three commits to settle how you move around the app.

LessonNavigation is one of the hardest UI problems — it encodes your whole mental model of the app. Expect to iterate. The mistake would have been to not commit between attempts and lose the ability to compare.

Redirect 3 — the big-bang refactor

22629fb changed 6 files and 2,272 lines at once; 9bb5508 rewrote popups in a 365/398 churn. Both were effectively un-reviewable.

Root cause, not symptomThese giant diffs weren't carelessness — they were forced by the monolith. When team detail, layout, and routing all live in one 1,600-line file, you can't change one without a diff that touches everything. The big-bang commit is a downstream symptom of poor file decomposition. Fix the structure (S8) and giant diffs become impossible.

Redirect 4 — a route became a popup

3614a78 deleted the /add route and replaced it with an in-place create/edit modal.

Lesson"Edit on a separate page" felt fine with two screens and wrong with four. UX truths are emergent — they only show up once the app is big enough to feel the friction. This is the strongest argument for the build-then-rebuild method: the first build generates the information the second build needs.

Redirect 5 — the pagination pivot the headline lesson

Early Tasks rendered all items and faked pagination by slicing in the browser (taskGroups, .slice(0, limit), "And 32 more"). The v1 finale tore that out for real server-side pagination: doc (3f8b033) → server endpoints (7747162) → client (64c21a5).

Before: client-side

Server sends all 60 items on bootstrap; the browser slices a window and shows "And N more." Simple, but it ships the entire dataset to every client and the counts are guesses from whatever happened to be loaded.

After: server-side

Server filters, sorts, slices, and returns { items, total, page, pageSize }. The client renders one page and trusts total. Scales to 60 or 60,000 the same way.

// the contract that made it honest — total computed BEFORE slicing
return { items: items.slice(start, start + pageSize), total, page: safePage, pageSize };
The deep lesson for a backend engineerClient-side pagination is a lie that scales to zero. Pagination, filtering, and sorting are server responsibilities — the place that owns the data owns the truth about how much there is. You already know this instinct from API design; the front end tempts you to forget it because slicing an array in the browser is so easy. Notice the discipline that made the redo clean: a design doc first, then the server, then the client, verified at each layer. That sequencing — not raw skill — is the difference between this feature and the big-bang refactor.

Redirect 6 — copy and alignment churn

Headers were rewritten to "action voice" (d0263e8: "Clear the backlog", "Meet the team"); the hero was centered site-wide on request; an "MVP" eyebrow was added and later retired (7747162); the Team CTA was renamed to "Manage team" across two commits because the first pass missed one spot.

LessonWords and alignment are part of the product, and they iterate like code. The "Manage team" rename needing a follow-up (4137aa7 → dcee8c6) is the classic "find-all-the-instances" miss — a duplicated string that should have been one constant. In the rebuild, label text lives in one place.

The meta-lesson: build to learn, rebuild to understand

Why the mess was the right first move Every redirect above produced information that didn't exist before the code did: that global color is noise, that a fourth screen makes modal editing necessary, that faked pagination collapses at scale. A spec couldn't have told you these — only a running, slightly-wrong app could. The first build's job is to generate that information cheaply. The rebuild's job is to bake the lessons into structure. You learned the front end by doing; you'll truly understand it by redoing — this time with the answers in hand.
