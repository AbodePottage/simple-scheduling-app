Field chronicle

How a backend engineer built a frontend in a weekend

A commit-by-commit autopsy of a real React + Node scheduling app — 35 commits, ~13 hours, from empty folder to a tagged v1 — rebuilt here as a crash course in TypeScript, HTML, and CSS.

35 commits ~13 hours React 19 + Express Tagged v1

What this is

This deck chronicles the actual construction of simple-scheduling-app — a small work-assignment tool inspired by Microsoft's Universal Resource Scheduling. It was built fast and a little messily, on purpose. The mess is the point: every reversal, every "temp" commit, every place the design wandered is a teaching moment.

You are a backend engineer. You read this to learn how the front of the house works — the three languages of the browser (HTML, CSS, TypeScript/JS), the React mental model, and how client concerns (state, layout, perceived speed) differ from the server concerns you already know. Then you hand the rebuild plan in S8 to a fresh agent and rebuild it clean, end-to-end, in a Docker container.

An honest disclaimer This version of the scheduler was built fast, with AI agents, and with only a limited understanding of the code underneath — a "hastily, though marvelously built" POC. That is not a confession to apologize for; it is the method. The core goal of this chronicle is to learn by doing, and to relearn by redoing: ship a rough thing to see the whole shape, study every place it wobbled, then rebuild it deliberately the second time. The mistakes catalogued here aren't failures to hide — they're the curriculum. You only understand why a clean architecture matters after you've felt the weight of a messy one.
How to read this Slides S1–S2 tell the story and map the architecture. Slides S3–S6 are the crash course, each grounded in real code from this repo. Slide S7 distills the mistakes. Slide S8 is the rebuild brief you'll feed to a tutorial-generating agent.

The stack, at a glance

LayerChoiceWhy it was picked (and the trade-off)
LanguageTypeScript everywhereOne language front and back. Types catch wiring mistakes the moment client and server disagree.
UI libraryReact 19Industry default; component model maps cleanly to "render this data." Trade-off: a whole mental model to learn.
Build/devViteInstant dev server + fast builds. Note: vite build uses esbuild and does not type-check the client.
BackendExpress 4, in-memory stateTiny API surface, zero database setup. Trade-off: data resets on restart — fine for a POC, not for real.
StateLocal React state onlyNo Redux/Zustand. useState + useMemo + useEffect. Honest for this size; strained by the end.
StylingHand-written CSS + custom propertiesNo framework. One styles.css with design tokens and a dark theme.

What the app actually does

  • Home — a dashboard: greeting, stat tiles, quick actions, jump-in links.
  • Schedule — a board: drag unscheduled work items onto resources; a timeline grid of bookings.
  • Team — two columns (Engineers / Data scientists) of equally-sized resource cards, paginated server-side.
  • Tasks — a flat, server-paginated backlog with filter/sort controls.

Four routes, one in-memory backend, eight seeded people and sixty seeded work items. Small enough to read in an afternoon, real enough to teach every core concept.
