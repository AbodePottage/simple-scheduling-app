Framework landscape

ReactAngularVue

S3–S6 teach React. Before diving in, it is worth knowing what you chose — and what you didn't. There are three serious options. They solve the same problem differently, and a .NET developer reads each one through a different lens.

This chronicle has not committed to ReactThe POC was built in React because it is the industry default and the right choice for a fast learning project. The NG slide after S6 shows every concept here translated directly into Angular. Read S3–S6 to understand the ideas; consult the NG slide when you need to apply them in Angular. The choice of framework for your real project is still open.

Angular through .NET eyes

Angular is the framework that feels most like ASP.NET, and deliberately so. It is opinionated, structured, and makes most decisions for you. The parallels are close enough to be immediately useful:

Angular.NET equivalent
ng new my-appdotnet new mvc -n MyApp
ng generate component tasksdotnet new razorcomponent -n Tasks
@Injectable({ providedIn: 'root' })services.AddSingleton<MyService>()
inject(WorkItemsService)Constructor injection in a controller
HTML template + *ngFor / @forRazor view + @foreach
[(ngModel)]="value"Two-way model binding in Blazor / Razor
HttpClient (built-in)HttpClient / IHttpClientFactory
Guards (CanActivate)Authorization middleware / filters
PipeIValueConverter / display formatters

The one genuinely unfamiliar concept is RxJS Observables — what Angular's HttpClient returns instead of Promises. Think of an Observable as a Task<T> that can emit multiple values over time and compose with operators like switchMap and combineLatest. Angular 17+ lets you convert Observables to Signals with toSignal(), which reduces the surface area you need to learn immediately. RxJS is Angular's steepest learning cliff; plan for it.

Vue in one paragraph

Vue sits between React and Angular on almost every axis. Its Single File Components (.vue files with a <template> block, a <script setup> block, and a <style scoped> block) are the closest thing in the frontend world to a Razor .cshtml: the template is genuine HTML, not JSX, and you write logic in a script section alongside it. Vue 3's Composition API (ref(), computed(), watch()) maps almost directly to React hooks. It has an official router (Vue Router) and official state management (Pinia). The learning curve is gentler than either React or Angular. Its market share is lower than both in the English-speaking enterprise world, but it is the dominant framework in parts of Asia and is widely used in smaller product teams. Worth knowing it exists; not the default choice for a .NET enterprise team starting fresh.

Why this chronicle chose React

  • Industry share. React is in roughly twice as many job listings as Angular and Vue combined. If the goal is transferable skill, React has the widest blast radius.
  • The mental model generalises. The concepts you learn in React — component functions, props, one-way data flow, hooks, the data-down/events-up discipline — transfer almost verbatim to Angular (Signals) and Vue (Composition API). Learn the ideas in React; read them in Angular with the NG slide as a dictionary.
  • Ecosystem velocity. TanStack Query, TanStack Router, Vite, and Vitest are fast-moving and widely adopted. The rebuild in S8–S10 uses this stack.
  • Vibe of the POC. The original build used React. Studying a real codebase beats studying examples.
How to choose for your real project If the project is greenfield and the team already knows .NET deeply — Angular's DI, structured CLI, and opinionated conventions will feel immediately productive. If the project is joining an existing React codebase — learn React well and treat the NG slide as reference. If the team is small and wants the gentlest ramp — Vue's template syntax and official tooling reduce decision fatigue. If you genuinely don't know yet — finish S3–S6 (React), read the NG slide (Angular), then decide. The concepts are the same; the syntax is a week of adjustment either way.
