CSS & the design system

1,663 lines, one filetokens · flex · grid

CSS is how the element tree becomes a look. It intimidates backend engineers because it's declarative and spatial rather than procedural — you describe rules, the browser lays things out. But the app's styles.css is built on four ideas that, once you see them, demystify the whole thing: tokens, the box, flexbox, and grid. Even this chronicle deck you're reading uses the same four.

1. A rule is a selector + declarations

.task-item {              /* selector: elements with class="task-item" */
  min-height: 76px;       /* declaration: property: value; */
  border: 1px solid var(--border);
}

You match elements (by class, mostly) and set properties. The app is "class-based": almost every style hangs off a className from the JSX, which keeps specificity flat and predictable.

2. Design tokens: custom properties are the system the app's best idea

The first 50 lines of styles.css define the entire visual language as CSS variables on :root. Every later rule references these — no hard-coded colors scattered around:

:root {
  --text: #1f2937;
  --surface: #ffffff;
  --border: #e5e7eb;
  --accent: #1d4ed8;
  --shadow: 0 18px 45px rgba(15, 23, 42, 0.08);
  --radius: 16px;
}

This is why the dark theme landed on commit 4 almost for free (S1, Phase 1). Dark mode is just a second set of values, applied when a data-theme attribute is on the root:

[data-theme='dark'] {
  --text: #e5e7eb;
  --surface: #111827;
  --border: #243041;
  --accent: #60a5fa;
}
// the toggle is one line of JS:
document.documentElement.dataset.theme = theme;   // 'light' | 'dark'
Why this worksComponents never name a color — they say color: var(--text). Flip the tokens at the root and the entire app (hundreds of rules) re-themes instantly. Tokens are to CSS what constants are to code: name the value once, change it in one place. This is the single highest-leverage habit to carry into the rebuild.

3. The box model: everything is a box

Every element is a rectangle: content, then padding, then border, then margin. The app sets the sane default that makes widths predictable:

* { box-sizing: border-box; }   /* width includes padding + border */

Without this, adding padding makes an element wider than the width you set — the classic "why is my layout off by 32px" beginner trap. border-box makes width mean what you expect.

4. Flexbox: one-dimensional rows and columns

Flexbox arranges children along a line and handles spacing/alignment. The centered hero — a thing the user explicitly asked for site-wide — is pure flex:

.hero {
  display: flex;
  flex-direction: column;   /* stack children vertically */
  align-items: center;      /* center across the line (horizontally here) */
  text-align: center;
}
.pagination {
  display: flex;
  align-items: center;
  gap: 0.75rem;             /* space between children, no margin hacks */
}

Reach for flex when you're laying out along one axis: a toolbar, a row of chips, a stack of cards. gap replaced the old margin-juggling era of CSS — use it.

5. Grid: two-dimensional layout

Grid places things in rows and columns at once. The Team page's two equal columns and the equi-sized resource cards (both explicit user requests) are grid:

.team-columns {
  display: grid;
  grid-template-columns: 1fr 1fr;   /* two equal columns */
  gap: 1.5rem;
}
.team-column .task-list {
  display: grid;
  grid-auto-rows: 76px;             /* every card the same height */
  align-content: start;
}
flex vs grid, decidedOne axis of stuff that should flow and wrap → flexbox. A real two-axis layout, or "make these all the same size" → grid. The 1fr 1fr means "two columns, split the space in equal fractions." minmax() + auto-fill (used in this deck's card grids) makes them responsive without media queries.

6. Responsive: adapt at breakpoints

@media (max-width: 880px) {
  .layout { grid-template-columns: 1fr; }   /* sidebar stacks under content */
}

A media query applies rules only when a condition holds (here, narrow screens). The two-column layout collapses to one. The app does some of this; doing it thoroughly is a known gap (mobile polish was a backlog item, not a finished feature).

7. State styling: hover, focus, selected

A UI has to react to the pointer and keyboard. Commit 1a122b8 ("Polish interaction states") was entirely this:

button:focus-visible { outline: 2px solid var(--accent); }   /* keyboard ring */
.task-item.selected { border-color: var(--accent); }        /* selected state */
.pagination-page.active { background: var(--accent); color: #fff; }

:focus-visible shows the ring for keyboard users but not mouse clicks — a small, thoughtful accessibility detail. ⚠ different Backend code has no concept of "hover" or "focus"; the front end is full of these in-between states, and forgetting them is what makes a UI feel cheap.

How the cascade actually bit this build

"CSS" = Cascading Style Sheets. When rules conflict, the winner is decided by specificity (how targeted the selector is) and source order. In a 1,663-line single file, that's a real hazard — a later, more-specific rule can silently override an earlier one. The colored-cards reversal (e7f2843 → 47464b8) was partly a cascade story: a broad rule colored too much, and the fix was to make the coloring rule more specific (board only).

The honest takeThis CSS was written with limited fluency, fast. It works and it's tokenized well, but 1,663 lines in one file is hard to navigate and easy to break by accident. The rebuild scopes styles per component (CSS Modules) so a rule can only ever hit the component it belongs to — no accidental cascade across the app.
The mental modelStyle with tokens so values live in one place; remember every element is a box; use flex for a line, grid for a plane; and never forget the in-between states (hover/focus/empty/disabled). That's 90% of real-world CSS, and it's all visible in this app's history.

Hands-on (15 min)

  1. Open styles.css and change --accent at :root to #9333ea. Reload — watch buttons, links, and active states all shift together. That's tokens.
  2. In devtools, select a .task-item and toggle box-sizing between content-box and border-box. Watch the width jump.
  3. Resize the window past 880px and back. Watch this deck's sidebar drop below the content — that's the media query firing.
